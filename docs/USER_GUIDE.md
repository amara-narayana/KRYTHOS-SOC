# KRYTHOS SOC — Operator & Analyst User Guide

> **Tagline:** Every Signal Connected. Every Threat Investigated.  
> **Target Environment:** Kali Linux / VirtualBox / Debian / Ubuntu / Windows 11  
> **Default Local URL:** [http://127.0.0.1:8000](http://127.0.0.1:8000)

---

## 1. Introduction

KRYTHOS SOC is a modular, local-first Security Operations Center platform designed to provide SIEM, log normalization, deterministic detection rules, MITRE ATT&CK mappings, alert triage, incident case management, and evidence-backed HTML reporting without requiring cloud subscriptions or paid external APIs.

---

## 2. Installation & Quick Start

### 2.1 Kali Linux / Ubuntu / VirtualBox

```bash
# Clone or navigate to the repository
cd krythos-soc

# Run the automated setup script
./scripts/setup.sh

# Start KRYTHOS SOC
./scripts/start.sh

# Check platform health
./scripts/healthcheck.sh
```

### 2.2 Windows 11 Host

```powershell
# In PowerShell:
.\scripts\start.ps1

# Or via Command Prompt:
.\scripts\start.bat
```

Navigate to `http://127.0.0.1:8000` in your web browser.

---

## 3. Initial Setup & First-Run Bootstrap

1. On initial startup, navigating to `http://127.0.0.1:8000` automatically displays the **First-Run Setup** screen.
2. Enter your desired Administrator credentials:
   - **Full Name:** e.g., `Security Administrator`
   - **Username:** e.g., `admin`
   - **Email:** e.g., `admin@krythos.local`
   - **Password:** Minimum 8 characters with upper, lower, and digit.
3. Click **"Initialize KRYTHOS SOC"**.
4. Once completed, the bootstrap endpoint is permanently locked. Future administrators can only be created by an existing administrator through the Admin UI or via the CLI:
   ```bash
   krythos user create --username analyst1 --email analyst1@krythos.local --role Analyst
   ```

## 4. Web GUI Navigation

The interface uses a dark navy and charcoal palette with high-density, accessible elements.

### 4.1 Overview Dashboard
- **Real-Time KPIs:** Total events ingested, open alerts categorized by severity, active incident cases, and data source health.
- **Volume Over Time:** Interactive timeline chart showing log volume trends.
- **Severity Breakdown:** Visual donut/bar representation of Critical, High, Medium, Low alerts.
- **Top Affected Hosts & Triggered Rules:** Direct drill-down links to filtered event and alert queries.

### 4.2 Event Explorer
- Search normalized security logs across all ingested sources.
- Structured filters for **Host**, **User**, **Source IP**, **Category**, and **Severity**.
- Switch between **Normalized View** (table) and **Raw View** (original syslog/JSON payload).
- Export filtered results directly to CSV.

### 4.3 Live Events Stream
- Live-polling event stream for near-real-time event monitoring.
- **Pause / Resume** controls with bounded memory buffers to prevent browser lag.
- Source filter dropdown to focus on specific feeds.

### 4.4 Alert Queue
- Triage newly triggered alerts generated by the detection engine.
- Filters for **Severity** (`critical`, `high`, `medium`, `low`) and **Status** (`new`, `acknowledged`, `resolved`, `closed`).
- Inspect supporting event evidence, rule logic explanations, and MITRE ATT&CK technique IDs.
- **Actions:** Acknowledge alert, assign to an analyst, or link to an active Incident Case.
- Optional **AI Assistant Drawer** providing offline local hypothesis generation.

### 4.5 Investigation Workbench (Cases)
- Create, track, and manage incident cases.
- **Priority & Status:** Track lifecycle from `new` &rarr; `investigating` &rarr; `contained` &rarr; `resolved` &rarr; `closed`.
- **Case Timeline:** Chronological analyst notes with timestamps and author signatures.
- **Evidence Locker:** Attached alerts and event IDs proving malicious activity.
- **Investigation Checklist:** Operational task tracking (e.g., Isolate Host, Block IP, Terminate Sessions).
- **Report Generation:** One-click export to standalone, self-contained HTML incident reports.

### 4.6 Entity Analytics
- Deep-dive into specific entities: **Users**, **Hosts**, and **IP Addresses**.
- Calculates an explainable **Risk Score (0–100)** with clear contribution breakdowns.
- Visualizes entity activity history and alerts.

### 4.7 Detection Rules
- Inspect all registered deterministic detection rules.
- View rule severity, MITRE ATT&CK tactic/technique mappings, and detection logic.
- Toggle rules **Active / Inactive**.
- Test rules against current database events with instant test feedback.

### 4.8 Threat Intelligence
- Local IOC database supporting **IP**, **Domain**, **URL**, and **File Hash (MD5/SHA256)**.
- Record confidence score, provenance source, and threat actor tags.
- Direct CSV import and export.
- 100% offline matching against incoming events.

### 4.9 MITRE ATT&CK Matrix
- Visual mapping of all active detection rules across Enterprise ATT&CK tactics:
  - *Initial Access*, *Execution*, *Persistence*, *Privilege Escalation*, *Defense Evasion*, *Credential Access*, *Lateral Movement*.
- Technique links to official MITRE knowledge base.

### 4.10 Reports & Evidence
- Access generated incident reports.
- View executive summaries, forensic evidence digests, and mitigation status.

### 4.11 Administration (Admins Only)
- User account lifecycle management (Create, Deactivate, Change Role).
- System settings and retention policy management.
- Complete immutable audit log viewer tracking sensitive operations.

## 5. Command-Line Interface (`krythos`)

The CLI shares the exact same database models and service layer as the web UI.

### 5.1 Common Commands

```bash
# Check platform status
krythos status

# Machine-readable output for scripts
krythos status --json

# Ingest a log file
krythos ingest /var/log/auth.log --source-type linux_auth

# Run detection rules on newly ingested events
krythos detect run

# List alerts
krythos alerts list --status new

# Inspect specific alert
krythos alerts show <ALERT_UUID>

# Search events
krythos events search --username root --limit 10

# Create incident case
krythos cases create --title "SSH Brute Force" --priority high

# Export case report
krythos report export --case-id <CASE_UUID> --format html --output report.html

# Database maintenance
krythos db check
krythos db backup
```
